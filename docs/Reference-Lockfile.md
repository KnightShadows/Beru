# Reference: Beru.lock

The `Beru.lock` file is automatically generated by Beru during the dependency resolution phase. It records the *exact* versions and sources of every direct and transitive dependency in your project.

## Purpose

While your `Beru.toml` might ask for a loose version constraint like `fmt = "10"`, the lockfile ensures that your build is **100% reproducible**. If you share your repository with a colleague, Beru will read the lockfile and download the exact same versions you used, even if a newer `10.x.x` version has been released.

## Should I commit `Beru.lock`?

This depends on what you are building:

- **Executables / Applications**: **YES**. Commit your `Beru.lock` to source control. This guarantees that all developers and CI pipelines build the application with identical dependency trees.
- **Libraries**: **NO**. Add `Beru.lock` to your `.gitignore`. When someone depends on your library, Beru ignores your lockfile and computes a fresh resolution tree based on the requirements of the top-level application.

## Format

The lockfile is written in TOML and contains an array of `[[package]]` entries. 

```toml
[[package]]
name = "fmt"
version = "10.2.1"
source = "registry"

[[package]]
name = "my_app"
version = "0.1.0"
dependencies = [
    "fmt 10.2.1",
]
```
*Note: You should never manually edit the `Beru.lock` file. It is entirely managed by the `beru resolve` and `beru build` commands.*
